Bản đồ hạ tầng — layered-infra

Hạ tầng mô phỏng on-prem dựng trên Google Cloud: 2 firewall OPNsense (biên đối mặt Internet, core lọc mọi luồng vào trong), vùng biên trong DMZ có HAProxy + WAF, quản trị qua VPN và jump server, cluster kubeadm, Harbor/Squid/kho S3 tự host, SIEM trong vùng quản trị. Google chỉ cung cấp phần không tránh được: VPC, route, VM, đĩa và IP public. Mọi thứ còn lại do Ansible cấu hình, dùng lại được khi triển khai on-prem thật.

Bốn luồng traffic

Vào: người dùng → app

  1. Client → IP public :443 → firewall-edge-01 (port forward)
  2. Port forward → HAProxy edge-01 (giải mã TLS)
  3. WAF (OWASP CRS) trên edge-01 lọc request
  4. HAProxy → Gateway 10.20.0.200 (TLS, qua firewall-core-01) → whoami

Kiểm thử: curl --resolve whoami.apps.lab.internal:443:<IP public> --cacert out/lab-ca.crt … → 200; gửi SQLi → 403.

Ra: node → Internet

  1. containerd kéo image qua Harbor (proxy-cache docker.io, registry.k8s.io, ghcr.io, quay.io)
  2. apt, curl, helm đi qua Squid :3128, chỉ tên miền trong allowlist
  3. Chỉ infra-01 được ra Internet 80/443: core cho (#140), biên cho (#20) và NAT ra IP public (Source NAT hybrid)

Kiểm thử: k8s-master-01 → example.com trực tiếp: bị chặn; qua Squid tới dl.k8s.io: 200; example.com qua Squid: bị chặn.

Quản trị: admin → mọi thứ

  1. Máy admin bật ./lab.sh vpn up (WireGuard, không cần sudo), IP 10.50.0.2
  2. VPN chỉ tới được jump-01:22 và GUI/API OPNsense :443 (cứu hộ, Ansible cấu hình firewall)
  3. ./lab.sh ssh <ip> và Ansible SSH xuyên qua jump-01 (ProxyCommand)
  4. ./lab.sh tunnel up: SOCKS 127.0.0.1:1080 qua jump-01 cho trình duyệt (Grafana, Harbor, Prometheus) và kubectl

Không VM nào có IP public ngoài firewall-edge-01. Từ VPN đi thẳng tới k8s-master-01:22 hay Grafana: bị chặn. Phiên SSH trên jump-01 được ghi lại (pam_tty_audit → auditd → SIEM).

Log: mọi máy → siem-01

  1. OPNsense: syslog TCP RFC5424 → siem-01:1514
  2. VM Linux: rsyslog (journal, auth, auditd) → siem-01:1514
  3. Wazuh agent → manager siem-01:1515/1516
  4. Alloy ghi vào Loki (bản sao trên infra-01); Grafana chạy luật cảnh báo → Mailpit
  5. Metric: Grafana đọc Prometheus trong cluster qua Gateway internal .210 (luật MGMT #215)

Mở luồng này bằng luật #25/#26 (DMZ), #160/#165 (LAN), #215 (MGMT).

Quy trình dựng từ con số 0

Nguyên tắc: image gốc của hãng + cấu hình bootstrap tối thiểu + Ansible làm phần còn lại. Không đóng cấu hình vào image, nên cùng một image dùng được cho GCP, lab local và on-prem thật.

  1. Golden image OPNsense

    ./lab.sh image

    Tạo VM Ubuntu tạm trong VPC WAN, tải OPNsense-26.7-nano-amd64.img.bz2 từ pkg.opnsense.org, kiểm tra SHA256, ghi lên đĩa phụ rồi tự tắt. GCP tạo image opnsense-26-7-nano từ đĩa đó; VM tạm và đĩa bị xoá.

    Tải trên GCP mất dưới 1 phút; qua Wi-Fi máy local sẽ mất hàng chục phút.

  2. Hạ tầng bằng OpenTofu

    ./lab.sh up

    Sinh 2 config bootstrap (out/opnsense-{edge,core}-bootstrap.xml) từ config.xml.sample đúng phiên bản 26.7, rồi tạo 4 VPC, 5 route VPC, VPC firewall tối thiểu, 2 IP public (web + VPN), 2 firewall (biên 2 card, core 3 card) và 6 VM Ubuntu 24.04 có user ubuntu + khoá SSH. Code chia 3 module dùng chung (provision/gcp/modules/{network,firewall,vm}); provision/gcp/main.tf đọc inventory Ansible ansible/shared/inventory/hosts.yml rồi gọi module.

    Bootstrap chỉ chứa: IP + MTU từng card, gateway .1 từng vùng (far gateway), route /25, mật khẩu root + API key riêng mỗi firewall, và 1 luật TẠM: biên cho IP public của admin gọi API trên WAN; core cho dải VPN gọi API trên card DMZ. Core: NAT tắt hẳn, card ngoài không chặn dải private; cả hai bỏ anti-lockout.

  3. Nạp bootstrap qua console nối tiếp

    ./lab.sh fw-bootstrap

    = ansible-playbook network/site.yml --tags bootstrap,firewall (bước này đến hết bước "Cấu hình đầy đủ qua VPN"). Hai script scripts/fw-console-bootstrap.py chạy song song, mỗi firewall một console: đăng nhập root/opnsense mặc định, chạy dhclient, thêm route tới 169.254.169.254, tải config từ metadata vào /conf/config.xml rồi khởi động lại.

  4. Dựng VPN qua WAN

    network/00-firewall-bootstrap.yml

    Ansible gọi API của biên qua IP public (chỉ IP của admin được phép), chỉ tạo WireGuard wg-admin, peer admin, alias và luật VPN. Máy admin bật kết nối NetworkManager gcp-lab; core lúc này đã gọi được xuyên VPN.

  5. Cấu hình đầy đủ qua VPN

    network/10-firewall.yml

    Cấu hình cả 2 firewall qua VPN (nhóm [firewalls], luật từng máy ở network/host_vars/firewall-*.yml): biên — luật VPN/DMZ, port forward, Source NAT hybrid; core — luật DMZ/LAN/MGMT, DNS nội bộ. Tắt "allow LAN to any", syslog → siem-01, xoá 2 luật BOOTSTRAP, siết SSH trên jump-01, DNS/NTP cho mọi VM, Squid trên infra-01.

  6. Cluster và dịch vụ

    ./lab.sh cluster

    Ansible chia 3 team, mỗi team một thư mục ansible/<team>/site.yml, chỉ trao đổi qua ansible/shared/ (inventory hosts.yml + hợp đồng); lab.sh cluster điều phối thứ tự giữa các team: network (firewall, egress mở tạm) → platform 20-kubernetes.yml (kubeadm, Cilium, CoreDNS đọc DNS mới) → 30-cluster-addons.yml (MetalLB, Gateway API, cert-manager, 2 Gateway) → 40-shared-services.yml (Harbor, mirror cho node, S3 Garage) → 50-apps.yml (whoami, cert vùng biên ghi ra out/edge-tls.pem) → nạp cache Harbor → network 20-edge.yml (HAProxy + WAF trên edge-01) + khoá egress → 2 nhánh song song → platform 80-backup.yml (Velero).

    Nhánh k8s (platform): 60-security.yml (Kyverno, hardening apiserver, backup etcd, kube-bench) → 70-metrics.yml (Prometheus). Nhánh ops: observability/site.yml (siem-01, bản sao log, rsyslog, auditd, Wazuh agent). Log từng nhánh ở out/logs/lane-*.log.

    Platform chạy với egress_temp_open=true vì Harbor chưa có cache. App nằm sau 40-shared-services.yml vì image kéo qua Harbor; vùng biên cần cert do cert-manager trong cluster cấp, nên network dựng vùng biên sau platform. Nhánh k8s phải tuần tự vì 60-security.yml khởi động lại kube-apiserver, Helm chạy cùng lúc sẽ lỗi.

Dựng lại từ đầu lần 2 (18/10/2026) sau khi tái cấu trúc Ansible, gom bootstrap vào site.yml và lấy mọi IP từ plan.yml: up → fw-bootstrap → cluster chạy một mạch không lỗi (cluster ~25 phút), kiểm thử đầu-cuối đạt hết.

Dựng lại từ đầu trên máy mới (17/10/2026, out/ trống) lộ 4 lỗi chỉ xuất hiện khi chưa có gì sẵn, đã sửa: tofu destroy đòi file bootstrap trong out/; khoá WireGuard admin chưa có script sinh (giờ lab.sh up tự sinh); 10-network.yml gọi kubectl khi chưa có cluster; whoami/WAF kéo image qua Harbor trước khi Harbor được cài.

Sinh tự động từ ansible/network/host_vars/firewall-{edge,core}-01.yml — đúng thứ Ansible đẩy lên OPNsense. Luật xét theo card nhận gói, số nhỏ trước, khớp là dừng; cuối mỗi card là luật chặn mọi thứ còn lại (ghi log → SIEM). Ngoài bảng: ở biên có port forward WAN 80/443 → edge-01 (giữ IP client) và Source NAT hybrid cho LAN/MGMT; core tắt NAT. Firewall VPC của GCP chỉ mở WAN 80/443/51820 vào máy gắn tag fw (biên).
